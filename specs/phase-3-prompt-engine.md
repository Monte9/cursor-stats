# Phase 3: Prompt → Chart Engine

> Goal: Users type natural language questions about their data and get dynamic, interactive charts generated by an LLM. Charts stack above the static dashboard, are deletable, and show the user's query.

---

## UX Vision

Inspired by Base44's prompt-first UX. The prompt box sits between the dashboard header and the static charts. User-generated charts stack on top of the static ones, pushing them down. Each generated chart shows the query that created it and can be deleted.

## Architecture

### Data Flow

```
User prompt
    ↓
Client: build context payload
  - CSV schema (column names + types)
  - UsageSummary stats (pre-computed, from stats.ts)
  - Sample rows (first 5 rows, for the LLM to understand data shape)
  - NOT the full CSV (privacy + token cost)
    ↓
POST /api/chart  (Next.js API route)
    ↓
Server: Vercel AI SDK → Claude 4.6 Sonnet
  - System prompt: "You are a data analyst. Given usage stats, generate a chart spec."
  - Returns: structured JSON (chart type, data, config, title, insight)
    ↓
Client: receives chart spec → Recharts renders it
    ↓
Chart added to user-generated stack (newest on top)
```

### What the LLM Receives (Context Payload)

The LLM never sees raw CSV rows. It receives:

```ts
interface ChartRequestPayload {
  prompt: string;                    // User's natural language query
  schema: string[];                  // Column names: ["Date", "User", "Kind", ...]
  summary: {
    totalRequests: number;
    totalCost: number;
    totalTokens: number;
    dateRange: { start: string; end: string };
    uniqueModels: number;
    byModel: { model: string; requests: number; cost: number; avgCostPerReq: number }[];
    byDay: { date: string; requests: number; cost: number }[];
    byHour: { hour: number; requests: number }[];
    byKind: { kind: string; count: number }[];
    cacheHitRate: number;
    errorRate: number;
    mostExpensiveRequest: { cost: number; model: string; date: string } | null;
    longestCodingStreak: number;
    busiestDay: { date: string; requests: number } | null;
  };
  sampleRows: Record<string, string>[]; // First 5 raw CSV rows (for schema understanding)
}
```

**Why this works:**
- The LLM can answer most questions from the aggregated stats alone
- Sample rows help it understand column formats and edge cases (e.g. Cost = "Free")
- Total payload is ~2-4K tokens — cheap per request
- Raw data stays client-side

### What the LLM Returns (Chart Spec)

```ts
interface ChartSpec {
  title: string;           // e.g. "Your Most Expensive Day"
  subtitle?: string;       // e.g. "March 15, 2026 — $247.32"
  insight?: string;        // e.g. "You spent 3x more on Fridays than Mondays"
  chartType: "bar" | "horizontalBar" | "line" | "pie" | "stat";
  data: Record<string, string | number>[]; // Chart data points
  xKey: string;            // Key for x-axis (e.g. "date", "model")
  yKey: string;            // Key for y-axis (e.g. "cost", "requests")
  yLabel?: string;         // Y-axis label format (e.g. "$", "requests")
  color?: string;          // Override chart color (default: orange-500)
}
```

**Chart type `"stat"`:** For questions that don't need a chart — just a big number + insight text. E.g. "How much did I spend on Opus?" → `{ title: "Opus Spending", subtitle: "$1,847.23", insight: "82% of your total spend", chartType: "stat" }`.

### Why Structured Output (Not Code Gen)

The LLM returns a JSON spec, NOT executable code or React components. Reasons:
- **Security:** No arbitrary code execution in the browser
- **Consistency:** All charts look the same (same Recharts config, same ChartCard wrapper, same tooltip styling)
- **Reliability:** Constrained output format is easier for the LLM to get right
- **Speed:** Small JSON payload, fast to parse and render

### 3.3 — API Route (`src/app/api/chart/route.ts`)

Next.js API route that:
1. Accepts POST with `ChartRequestPayload`
2. Validates the request (prompt length, payload size)
3. Builds a system prompt + user message for the LLM
4. Calls Claude 4.6 Sonnet via Vercel AI SDK with `generateObject()` for structured output
5. Returns the `ChartSpec` JSON
6. Rate limiting: simple in-memory counter per IP (e.g. 20 requests/hour)

**System prompt (draft):**
```
You are a data visualization analyst for CursorStats, a tool that helps developers understand their Cursor AI usage.

Given a user's usage statistics summary, generate a chart specification that best answers their question.

Rules:
- Use ONLY the data provided in the summary. Do not invent data points.
- Pick the chart type that best communicates the answer (bar for comparisons, line for trends, pie for proportions, stat for single numbers).
- For "stat" type: return a big headline number in subtitle with a brief insight.
- The data array must contain concrete values derived from the summary stats.
- Keep titles short (5-8 words). Insights should be one sentence, surprising or actionable.
- Format costs as numbers (not strings with $). The frontend handles formatting.
- When the question is ambiguous, prefer the most interesting/surprising interpretation.
```

**Model selection:**
- Primary: `claude-4.6-sonnet` (fast, cheap, good at structured output)
- Fallback: `claude-4.6-opus` (if Sonnet fails or returns invalid JSON — automatic retry)

**Error handling:**
- LLM returns invalid JSON → retry once with Opus
- LLM hallucinates data not in summary → client-side validation (check if values are plausible)
- Rate limit exceeded → return 429 with "Try again in X minutes"
- API key missing → return 500 with setup instructions (dev only)

### 3.5 — Prompt Input Component (`src/components/app/prompt-input.tsx`)

UI component positioned between the dashboard header and charts:

- **Text input:** Multi-line textarea with placeholder "Ask about your usage..."
- **Submit button:** Orange arrow/send icon, disabled while loading
- **Suggestion pills:** Row of clickable pills below the input
  - "What's my most expensive model?"
  - "Show me my daily spending trend"
  - "When am I most active?"
  - "Compare my model usage"
  - "What's my cache efficiency?"
- **Loading state:** Skeleton chart card pulses while LLM responds
- **Error state:** Red inline message below input if API fails

**Behavior:**
- Enter key submits (Shift+Enter for newline)
- Clicking a pill fills the input and auto-submits
- Input clears after successful submission
- Disabled during loading (prevent double-submit)

### 3.6 — Dynamic Chart Renderer (`src/components/app/dynamic-chart.tsx`)

Renders a `ChartSpec` as a ChartCard:

- Wraps in the same `ChartCard` component (macOS dots, watermark)
- Shows the user's query above the card in muted text
- Delete button (✕) in the top-right corner of the query label
- Supports all chart types: bar, horizontalBar, line, pie, stat
- Uses the same tooltip styling as static charts
- Fade-in animation on mount (Framer Motion)

**For `"stat"` type:**
- Large title text
- Huge subtitle number (4xl, orange-500)
- Insight text below in muted

### 3.7 — Chart Stack State Management

In the dashboard component, manage user-generated charts:

```ts
interface GeneratedChart {
  id: string;          // uuid
  prompt: string;      // User's original query
  spec: ChartSpec;     // LLM response
  createdAt: Date;
}

const [generatedCharts, setGeneratedCharts] = useState<GeneratedChart[]>([]);
```

- New charts prepend to the array (newest first)
- Delete removes by id
- Charts render between prompt input and static dashboard
- No persistence — refresh clears generated charts (same as CSV data)

### 3.8 — Wire It Together

Update `src/components/app/dashboard.tsx`:

1. Add `<PromptInput>` between header and chart grid
2. On submit: POST to `/api/chart` with payload → receive spec → prepend to `generatedCharts`
3. Render `generatedCharts.map(c => <DynamicChart>)` between prompt input and static charts
4. Pass `onDelete` handler to each dynamic chart

Also update `src/app/demo/page.tsx` — demo mode should also support prompts (it has the same data).

## Rate Limiting Strategy

Simple in-memory rate limiter for the API route:

```ts
// Map<IP, { count: number; resetAt: number }>
const rateLimits = new Map();
const LIMIT = 20;         // requests per window
const WINDOW_MS = 3600000; // 1 hour
```

**Why in-memory is fine for now:**
- Single Vercel serverless instance handles most traffic at this scale
- If we need distributed rate limiting later, swap for Upstash Redis (one-line change with `@upstash/ratelimit`)
- For launch scale, in-memory is sufficient

**What the user sees:**
- First 20 queries/hour: normal
- After limit: "You've used all your queries for this hour. Try again in X minutes." (friendly, not angry)

## LLM Cost Estimate

Per query:
- Input: ~2-4K tokens (system prompt + summary + user prompt)
- Output: ~200-500 tokens (chart spec JSON)
- Cost per query: ~$0.01-0.02 (Sonnet)
- At 20 queries/user/hour: ~$0.20-0.40/user/session

At 100 daily active users: ~$20-40/day. Manageable for launch.

## Edge Cases

1. **Question unrelated to data:** LLM should respond with `chartType: "stat"` and `insight: "I can only analyze your Cursor usage data. Try asking about models, costs, or usage patterns."`
2. **Question requires data not in summary:** LLM should use the closest available data and note the limitation in `insight`.
3. **Very short query:** ("cost") — LLM interprets as "show me my total cost breakdown"
4. **Very long query:** Client-side limit of 500 characters
5. **No data loaded:** Prompt input should be disabled if no CSV/demo data is present
6. **Concurrent requests:** Disable input during loading, queue if needed
7. **Network error:** Show retry button below input
