# Phase 3: Prompt → Chart Engine

> Goal: Users type natural language questions about their data and get dynamic, interactive charts generated by an LLM. Charts appear above the static dashboard.

---

## UX

Prompt box sits between the dashboard header and the static charts. User types a question → LLM returns a chart config → Recharts renders it using real data from `UsageSummary`. Single chart slot for launch (new query replaces previous). Suggestion pills for quick-start.

**Layout:**

## Architecture

### Core Principle: LLM Selects, Client Resolves

**The LLM does NOT generate data.** It picks from existing pre-computed data sources in `UsageSummary` and configures how to display them. The client resolves the `dataSource` reference against real data. Zero hallucination risk for numbers.

Available data sources the LLM can reference:

| dataSource | Shape | Available Fields |
|------------|-------|-----------------|
| `byModel` | `{ model, requests, cost, tokens, avgCostPerReq }[]` | model, requests, cost, tokens, avgCostPerReq |
| `byDay` | `{ date, requests, cost }[]` | date, requests, cost |
| `byHour` | `{ hour, requests }[]` | hour, requests |
| `byDayOfWeek` | `{ day, requests, cost }[]` | day, requests, cost |
| `byKind` | `{ kind, count }[]` | kind, count |

For `stat` chart type, the LLM references a `statKey` from top-level summary fields:

| statKey | Type | Example |
|---------|------|---------|
| `totalCost` | number | 3387.86 |
| `totalRequests` | number | 20817 |
| `totalTokens` | number | 343266072 |
| `avgCostPerRequest` | number | 0.16 |
| `cacheHitRate` | number | 0.972 |
| `errorRate` | number | 0.023 |
| `uniqueModels` | number | 7 |
| `longestCodingStreak` | number | 15 |

### Data Flow

```
User prompt
    ↓
Client: build payload
  - prompt (string, max 500 chars)
  - summary (serialized UsageSummary — aggregated stats only)
  - NO raw CSV rows, NO sample rows
    ↓
POST /api/chart  (Next.js API route)
    ↓
Server: generateObject() with Zod schema
  - Model: Claude 4.6 Sonnet (only, no Opus fallback)
  - System prompt with few-shot examples
  - Returns: ChartSpec (dataSource reference + chart config)
    ↓
Client: resolve dataSource against local UsageSummary
    ↓
Recharts renders in ChartCard
```

## Types (`src/lib/types.ts`)

```ts
import { z } from "zod";

// What the LLM returns (Zod schema for generateObject)
export const chartSpecSchema = z.object({
  title: z.string().describe("Short chart title, 5-8 words"),
  subtitle: z.string().optional().describe("Key stat or date range"),
  insight: z.string().optional().describe("One surprising or actionable sentence"),
  chartType: z.enum(["bar", "horizontalBar", "line", "pie", "stat"])
    .describe("horizontalBar = Recharts BarChart with layout='vertical'"),
  // For chart types (bar, horizontalBar, line, pie):
  dataSource: z.enum(["byModel", "byDay", "byHour", "byDayOfWeek", "byKind"])
    .optional()
    .describe("Which UsageSummary breakdown to visualize"),
  xKey: z.string().optional().describe("Field name for x-axis / labels"),
  yKey: z.string().optional().describe("Field name for y-axis / values"),
  yLabel: z.string().optional().describe("Y-axis format hint: '$' or 'requests' or 'tokens'"),
  sortBy: z.string().optional().describe("Optional: re-sort data by this field"),
  limit: z.number().optional().describe("Optional: show only top N items"),
  // For stat type:
  statKey: z.string().optional()
    .describe("For stat charts: key from top-level summary (e.g. 'totalCost', 'cacheHitRate')"),
});

export type ChartSpec = z.infer<typeof chartSpecSchema>;

// What we send to the API
export interface ChartRequestPayload {
  prompt: string;
  summary: SerializedSummary;
}

// UsageSummary with Dates serialized to strings
export interface SerializedSummary {
  totalRequests: number;
  totalCost: number;
  totalTokens: number;
  dateRange: { start: string; end: string };
  uniqueModels: number;
  byModel: { model: string; requests: number; cost: number; tokens: number; avgCostPerReq: number }[];
  byDay: { date: string; requests: number; cost: number }[];
  byHour: { hour: number; requests: number }[];
  byDayOfWeek: { day: string; requests: number; cost: number }[];
  byKind: { kind: string; count: number }[];
  cacheHitRate: number;
  errorRate: number;
  avgCostPerRequest: number;
  mostExpensiveRequest: { cost: number; model: string; date: string } | null;
  longestCodingStreak: number;
  busiestDay: { date: string; requests: number } | null;
}
```

### 3.4 — API Route (`src/app/api/chart/route.ts`)

Next.js API route:
1. Accept POST with `{ prompt, summary }`
2. Validate prompt length (≤500 chars, server-side)
3. Call `generateObject()` with Zod schema + system prompt
4. Return the `ChartSpec` JSON
5. No rate limiting for launch — monitor spend on Anthropic dashboard

**System prompt with few-shot examples:**

```
You are a data visualization analyst for CursorStats. Given a user's Cursor AI usage summary, generate a chart specification that answers their question.

You must select from these data sources (pre-computed, real data):
- byModel: [{model, requests, cost, tokens, avgCostPerReq}] — per-model breakdown
- byDay: [{date, requests, cost}] — daily breakdown
- byHour: [{hour, requests}] — requests by hour of day (0-23)
- byDayOfWeek: [{day, requests, cost}] — Mon through Sun
- byKind: [{kind, count}] — request type breakdown

For stat-type answers, reference these summary keys:
totalCost, totalRequests, totalTokens, avgCostPerRequest, cacheHitRate, errorRate, uniqueModels, longestCodingStreak

Rules:
- NEVER invent data. Only reference the data sources and keys listed above.
- Pick the chart type that best communicates the answer.
- horizontalBar = bar chart with layout="vertical" (good for comparing named items like models).
- Keep titles short (5-8 words). Insights should be one surprising or actionable sentence.
- For costs, set yLabel to "$". For counts, set yLabel to "requests" or "tokens".

Examples:

User: "What's my most expensive model?"
Response: { "chartType": "horizontalBar", "dataSource": "byModel", "xKey": "model", "yKey": "cost", "title": "Cost by Model", "yLabel": "$", "sortBy": "cost", "limit": 6, "insight": "Opus accounts for 82% of your total spend" }

User: "When am I most active?"
Response: { "chartType": "bar", "dataSource": "byHour", "xKey": "hour", "yKey": "requests", "title": "Requests by Hour", "yLabel": "requests", "insight": "You're most productive between 5-8pm" }

User: "What's my cache hit rate?"
Response: { "chartType": "stat", "statKey": "cacheHitRate", "title": "Cache Hit Rate", "subtitle": "97.2%", "insight": "Only 2.8% of your tokens are fresh computation" }
```

**Error handling:**
- `generateObject()` fails → return 500 with user-friendly message
- Prompt too long → return 400
- API key missing → return 500 with setup hint (dev only)

### 3.5 — Prompt Input Component (`src/components/app/prompt-input.tsx`)

- **Textarea** with placeholder "Ask about your usage..."
- **Submit button:** Orange arrow icon, disabled while loading
- **Suggestion pills** below input:
  - "What's my most expensive model?"
  - "Show my daily spending trend"
  - "When am I most active?"

- **Loading state:** Skeleton chart card pulses below input while LLM responds
- **Error state:** Red inline message below input

- Clicking pill fills input + auto-submits
- Input clears after success
- Disabled during loading

### 3.6 — Dynamic Chart Renderer (`src/components/app/dynamic-chart.tsx`)

Renders a `ChartSpec` by resolving `dataSource` against local `UsageSummary`:

1. Look up `spec.dataSource` in stats (e.g. `"byModel"` → `stats.byModel`)
2. Apply `sortBy` and `limit` if specified
3. Map `horizontalBar` → `<BarChart layout="vertical">`
4. Render in `ChartCard` with user's query shown above
5. Dismiss button (✕) clears the generated chart
6. Fade-in animation on mount

**For `"stat"` type:**
- Look up `spec.statKey` in stats (e.g. `"cacheHitRate"` → `stats.cacheHitRate`)
- Format based on `yLabel` hint or key name (costs get `$`, rates get `%`)
- Render: large title, huge number (4xl orange), insight text

**`horizontalBar` mapping note:** Recharts has no `horizontalBar` component. Map it to `<BarChart layout="vertical">` with `<XAxis type="number">` and `<YAxis type="category">`. This is what the existing static charts already do.

### 3.7 — Wire Into Dashboard

Update `src/components/app/dashboard.tsx`:

1. Add `<PromptInput>` between header and chart grid
2. Single state: `const [generatedChart, setGeneratedChart] = useState<{ prompt: string; spec: ChartSpec } | null>(null)`
3. On submit: POST to `/api/chart` → set `generatedChart`
4. Render `<DynamicChart>` between prompt and static charts (if present)
5. Dismiss clears `generatedChart`
6. New query replaces previous

Dashboard needs access to both `UsageSummary` (for chart rendering) and raw serialized summary (for API payload). Inline the Date → string serialization (~5 lines in the submit handler).

Update `src/app/demo/page.tsx` and `src/app/app/page.tsx` — both need to pass data through for prompt support.

**Note:** `byHourInDay` is conditionally populated (single-day only). Exclude it from available data sources — the LLM shouldn't reference it. `byHour` is always present and covers the same use case.

## Edge Cases

1. **Unrelated question:** LLM returns `stat` type with insight: "I can only analyze your Cursor usage data."
2. **Question needs unavailable data:** LLM picks closest data source, notes limitation in insight
3. **Very short query** ("cost"): LLM interprets broadly, picks `byModel` + `cost`
4. **Query > 500 chars:** Rejected client-side and server-side
5. **No data loaded:** Prompt input disabled
6. **LLM returns invalid dataSource:** Client falls back to error message ("Couldn't generate that chart. Try a different question.")
7. **Network error:** Show retry button below input

## LLM Cost Estimate

Per query (Sonnet only):
- Input: ~2-3K tokens (system prompt + summary)
- Output: ~100-300 tokens (ChartSpec JSON)
- Cost per query: ~$0.01-0.02
- No Opus fallback → predictable costs

Monitor on Anthropic dashboard. If abuse detected, add Upstash rate limiting.
